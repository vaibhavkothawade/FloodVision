Great choice. Below is a **beginner-friendly, team-of-three roadmap** to build **FloodLens: AI Flood Impact Copilot** in 4–6 weeks, with:

- What each person should learn
- A week-by-week plan
- Concrete tasks split between 3 people
- Resources and starter code ideas

I’ll assume:
- You’re all **beginners** in Python + ML + geospatial.
- You have **~10–15 hours/week** each.
- You want a **solid MVP + good demo**, not a perfect research system.

***
## 0. Roles for a 3-person team
Give each person a primary role, but everyone helps with demo and polish.
### Person A – Geospatial & Data Engineer
**Focus:** Satellite data, GIS, maps, backend data pipeline.

- Learn: Python basics, GeoPandas, Rasterio, QGIS, basic coordinate systems.
- Owns:
  - Downloading and preprocessing satellite imagery (Sentinel-2 / Landsat).
  - Creating flood masks or using existing labels.
  - Building the map backend (tiles, layers).
  - GIS risk scoring (population, roads, buildings).
### Person B – Computer Vision / ML Engineer
**Focus:** Flood segmentation model, training, evaluation.

- Learn: Python, PyTorch, U-Net basics, training loops, metrics (IoU).
- Owns:
  - Implementing a U-Net or similar model for water/flood segmentation.
  - Training on a flood dataset (e.g., Sen1Floods11, Cloud to Street–Microsoft).
  - Exporting predictions as rasters/GeoTIFFs.
  - Simple evaluation notebook and metrics.
### Person C – Frontend & Generative AI Agent
**Focus:** Web dashboard, UI, LLM integration, story.

- Learn: Streamlit basics, Leaflet/MapLibre, simple LLM prompt engineering.
- Owns:
  - Building the Streamlit web app.
  - Displaying map layers (before/after, flood mask, risk scores).
  - Connecting predictions and GIS data to a simple LLM “agent”.
  - Designing the demo flow and presentation.

> Everyone learns Python first. Then you split by role.

***
## 1. Core tech stack you need to learn
You don’t need to master everything; just enough to build the MVP.
### Common to all
- **Python basics**
  - Variables, functions, loops, modules, virtual environments.
  - Use Google Colab or local env with `venv` or `conda`.
### Person A (Geospatial & Data)
- **GeoPandas** – handling shapefiles, GeoJSON.
- **Rasterio** – reading/writing GeoTIFFs.
- **QGIS** – visual inspection of maps (GUI, no coding).
- **Sentinel Hub / Google Earth Engine** – downloading imagery.
- Basic concepts:
  - Coordinate Reference Systems (CRS), reprojecting.
  - Raster vs vector data.
### Person B (CV / ML)
- **PyTorch** (or TensorFlow) – tensors, models, dataloaders.
- **U-Net architecture** – encoder-decoder, skip connections.
- Training basics:
  - Loss functions (BCE, Dice), optimizers, epochs.
  - Train/validation split, overfitting detection.
- Libraries:
  - `torchvision`, `albumentations` (for augmentations).
### Person C (Frontend + Agent)
- **Streamlit** – simple Python web apps.
- **Leaflet / Folium / MapLibre** – interactive maps in Python.
- **LLM basics** – prompt templates, function calls, simple RAG (optional).
- **JSON/GeoJSON** handling for map data.

## 2. Datasets to target (beginner-friendly)
Use existing labeled datasets so you don’t waste time labeling.

Good options:

1. **Sen1Floods11** (Sentinel-1 + Sentinel-2 flood dataset)
   - Global, with flood masks.
   - Used in many papers and tutorials.
2. **Cloud to Street – Microsoft Flood Dataset**
   - Sentinel-1 chips with water labels.
   - Used in U-Net flood segmentation repos. [github](https://github.com/chathumal93/Pytorch-UNet-Flood-Segmentation)
3. **FloodNet / other Kaggle flood datasets**
   - Smaller, easier for quick prototyping.

As a beginner, it’s fine to:
- Start with a **small subset** of the dataset.
- Use **pretrained U-Net code** and adapt it to the data. [github](https://github.com/gabboraron/Nvidia-Disaster_Risk_Monitoring_Using_Satellite_Imagery)

***
## 3. High-level architecture (for your MVP)
Keep it simple but realistic:

1. **Data layer**
   - Satellite images (GeoTIFF) + labels (water/flood mask).
   - GIS layers: roads, buildings, population (shapefile/GeoJSON).
2. **Model layer**
   - U-Net model predicting flood vs non-flood per pixel.
   - Outputs: flood mask GeoTIFF or PNG with georeferencing.
3. **Risk scoring layer**
   - Use flood mask + GIS layers to compute:
     - Number of buildings in flood.
     - Length of roads in flood.
     - Population affected.
4. **Agent layer**
   - Take summary stats + map metadata.
   - Prompt LLM to generate:
     - “Incident summary”
     - “Recommended actions”
5. **Frontend**
   - Streamlit app with:
     - Map (before/after, flood mask, risk hotspots).
     - Dropdown to select flood event / region.
     - Text panel with AI summary.

## 4. 6-week roadmap (with learning + tasks)
I’ll assume you can adjust to 4–5 weeks by compressing Weeks 5–6 if needed.
### Week 0 (pre-work, 2–3 days if possible)
**Goal:** Everyone can run basic Python code and a simple tutorial.

- All:
  - Install Python, VS Code or PyCharm, and Git.
  - Do a **basic Python crash course** (loops, functions, notebooks).
  - Each person: run a “Hello World” script and a small notebook.

Resources:
- “Python for Everybody” (free online).
- Any “Python for data science” crash course on YouTube.

***
### Week 1 – Foundations + project setup
**Learning goals**

- All:
  - Basic Git: clone repo, commit, push.
  - Basic project structure: `src/`, `data/`, `notebooks/`, `app/`.

- Person A:
  - Learn GeoPandas + Rasterio basics.
  - Install QGIS and open a sample GeoTIFF/shapefile.
- Person B:
  - Learn PyTorch basics: tensors, simple CNN.
  - Run a U-Net tutorial on a toy dataset (e.g., segmentation on Cityscapes or a small custom dataset).
- Person C:
  - Learn Streamlit basics: text, buttons, simple plots.
  - Build a minimal app that shows a static image and some text.

**Project tasks**

- All:
  - Create a shared GitHub repo.
  - Write a short `README.md` with:
    - Problem statement.
    - Team members + roles.
    - Planned tech stack.
  - Agree on one **pilot region** (e.g., a known flood area like Pakistan 2022, or a specific river basin).

- Person A:
  - Download **one small flood dataset** (e.g., a few chips from Sen1Floods11 or Cloud to Street).
  - Visualize:
    - Raw satellite image.
    - Corresponding flood mask.
  - Save a small sample in `data/sample/`.

- Person B:
  - Clone a U-Net segmentation repo (e.g., a simple PyTorch U-Net).
  - Adapt it to read the sample data from Person A.
  - Get a **very basic training loop** running (even if accuracy is low).

- Person C:
  - Build a **Streamlit skeleton app**:
    - Title: “FloodLens – AI Flood Impact Copilot”.
    - A simple map (can be static for now).
    - A text box that says “AI incident summary will appear here”.

**End of Week 1 success:**  
You have a repo, a tiny dataset, a U-Net that runs (even poorly), and a bare-bones Streamlit app.

***
### Week 2 – Data pipeline + baseline model
**Learning goals**

- Person A:
  - Learn how to download more imagery from:
    - Google Earth Engine (Python API) or
    - Sentinel Hub.
  - Learn basic preprocessing:
    - Clip to AOI.
    - Convert bands to arrays for model input.
- Person B:
  - Improve U-Net training:
    - Better loss (BCE + Dice).
    - Validation split.
    - Basic metrics (IoU).
- Person C:
  - Learn Folium or Leafmap for interactive maps.
  - Learn how to display GeoTIFFs/PNG overlays on a map.

**Project tasks**

- Person A:
  - Build a script `download_data.py` that:
    - Takes a bbox + date range.
    - Downloads Sentinel-2 or uses existing flood dataset chips.
  - Create a **train/val split** CSV or JSON with file paths.
  - Document how to run `download_data.py` in the README.

- Person B:
  - Train U-Net on the full small dataset.
  - Evaluate on a test set and log IoU.
  - Save best model weights.
  - Create a notebook:
    - Load model.
    - Run inference on a sample image.
    - Show predicted flood mask vs ground truth.

- Person C:
  - In Streamlit:
    - Add a map (Folium/Leafmap).
    - Display:
      - Base satellite image.
      - A static flood mask overlay (from Person B’s output).
  - Add a dropdown to select between 1–2 sample events/regions.

**End of Week 2 success:**  
You can run inference on a few images and see flood masks on a map in your app.

***
### Week 3 – GIS risk scoring + better model
**Learning goals**

- Person A:
  - Learn how to:
    - Load road and building shapefiles (OpenStreetMap via Geofabrik or similar).
    - Intersect flood mask with roads/buildings/population grid.
- Person B:
  - Experiment with:
    - Data augmentation (rotations, flips, brightness).
    - Slightly deeper model or pretrained encoder.
- Person C:
  - Learn how to:
    - Call an LLM API (OpenAI-compatible or local).
    - Build prompt templates.

**Project tasks**

- Person A:
  - Build `risk_scoring.py`:
    - Input: flood mask GeoTIFF + AOI.
    - Output:
      - Number of buildings in flood.
      - Length of roads in flood.
      - Approx population affected.
    - Save as JSON with per-zone stats.
  - In QGIS, visually verify that overlays make sense.

- Person B:
  - Improve model:
    - Add augmentations.
    - Try a known U-Net variant (e.g., from a GitHub repo).
  - Generate predictions for 2–3 real flood events.
  - Export predictions as GeoTIFFs or PNGs with georeferencing.

- Person C:
  - In Streamlit:
    - Add a “Risk Summary” panel.
    - Show:
      - Tables of affected buildings/roads/population.
      - Simple bar charts (Plotly) for these metrics.
  - Integrate LLM:
    - Create a prompt like:
      - “You are a disaster response assistant. Here are stats from a flood event: {stats}. Summarize the situation and suggest 3 priority actions for responders.”
    - Call the LLM with stats from Person A.
    - Display the response in the app.

**End of Week 3 success:**  
Your app shows flood maps, risk metrics, and a basic AI-generated incident summary.

***
### Week 4 – Full pipeline + multi-event demo
**Learning goals**

- Person A:
  - Learn basic tiling or caching so maps load faster.
  - Learn how to add a “before/after” slider conceptually (even if simple).
- Person B:
  - Learn how to:
    - Batch inference over multiple images.
    - Save outputs in a structured way.
- Person C:
  - Learn how to:
    - Design a clear demo flow.
    - Add simple navigation (tabs or sections) in Streamlit.

**Project tasks**

- Person A:
  - Prepare **2–3 flood events** (different regions or dates).
  - For each event:
    - Precompute:
      - Satellite base image.
      - Flood mask.
      - Risk stats JSON.
  - Store in `data/events/event_name/`.

- Person B:
  - Create a script `run_inference_event.py`:
    - Takes event folder as input.
    - Runs model over all images.
    - Saves flood masks.
  - Ensure inference runs in reasonable time (optimize batch size, maybe use GPU if available).

- Person C:
  - Redesign Streamlit app with sections:
    1. “Overview” – short description of FloodLens.
    2. “Map & Risk” – dropdown to select event, map with flood mask, risk stats.
    3. “AI Incident Report” – text panel with LLM summary.
  - Add a “Demo Mode” button that:
    - Loads a specific event.
    - Shows a guided walkthrough (e.g., “Step 1: See before image”, “Step 2: See flood mask”, etc.).

**End of Week 4 success:**  
You have a working end-to-end demo for 2–3 flood events.
